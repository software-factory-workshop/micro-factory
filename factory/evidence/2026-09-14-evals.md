Factory changes (micro-factory `6573244`, `e76e3b7…`; Jira factory PR for the same snapshot change):
- Snapshots load from one `tarball/<revision>` request, each entry verified against the blob id from the tree, per-blob read as fallback. A run drops from roughly 300 GitHub calls to about 20.
- A gate that stops before `record_review` is restarted, at most twice per gate (`retryGate`), before the delivery stops for a person.
- GitHub error messages carry the API message and rate-limit headers; reads retry on 403/429 with `retry-after` and on 5xx.
