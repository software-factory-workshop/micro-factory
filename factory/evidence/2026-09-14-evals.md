## Incident · 15 September 00:30–01:16 CEST · shared GitHub App budget exhausted

The first two cockpit deliveries on Sol Fast reached `working` and then stopped: `prepare_review` (delivery `7ce03861…`, PR #9 published after 8 minutes) and then `prepare_work` (delivery `c4370565…`) returned `Factory GitHub request failed: HTTP 403. API rate limit exceeded for installation ID 161088937 … resets 2026-09-14T23:16:11Z`. The Jira factory's task-mining evals failed at the same time for the same reason. The installation is shared by the micro-factory, the Jira factory and a Codex agent that was feeding the Jira factory a new draft every 20 seconds.

Factory changes (micro-factory `6573244`, `e76e3b7…`; Jira factory PR for the same snapshot change):
- Snapshots load from one `tarball/<revision>` request, each entry verified against the blob id from the tree, per-blob read as fallback. A run drops from roughly 300 GitHub calls to about 20.
- A gate that stops before `record_review` is restarted, at most twice per gate (`retryGate`), before the delivery stops for a person.
- GitHub error messages carry the API message and rate-limit headers; reads retry on 403/429 with `retry-after` and on 5xx.
